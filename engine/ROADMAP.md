## 다음 단계 (순서대로, 각자 게이트 있음)

### v2.3 — 실측 재보정 (실물 도착 후 즉시 가능)
- **무엇**: 팀 실기기 테스트(3조명×3회×N명, **시간대 통제 — 일중 피지 변동 ±30%, 피크 13:20**)에서 `?bfmdebug` 런로그 수집 → `calibrate.mjs`로
  CAL(shineFull·dryZero·redOffset·poreDen·rough) 재보정 + troubleMin↔C비율 표로 대표가 배분 결정.
- **왜**: 지금 상수는 합성 스윕 기준 — 실폰 카메라 분포로 한 번 앵커를 잡아야 함.
- **게이트**: 재보정 후 run-baseline 회귀 + 같은 사람 재촬영 2회 일치 확인.
- **비용**: 코드 0 (도구는 이미 있음), 테스트 세션 1회.

### v2.4 — 업로드 경로 얼굴 검증 (FINDINGS R4)
- **무엇**: 파일 업로드 사진에도 BlazeFace 1회 실행 — 얼굴 없으면 q 하향 + "설문 위주 판정" 정직 표시.
  검출되면 촬영 경로처럼 키포인트 ROI·오염원 제외도 적용(지금은 업로드가 중앙박스 폴백).
- **왜**: 인스타 인앱 사용자(업로드 경로)가 실제 유입의 큰 몫 — 지금은 벽 사진도 지수가 나옴.
- **게이트**: 업로드 경로 E2E + 모델 로드 지연(1~2초)이 UX를 깨지 않는지 폰 확인.

### v2.5 — 세션 간 일관성 (재진단 안정화) — 절반 완료(v2.3 히스테리시스). 남은 것: 조명조건 차이 안내 문구
- **무엇**: 런로그에 남는 직전 측정과 신규 측정을 비교해, 조명 조건이 크게 다르면
  "지난번과 촬영 환경이 달라요" 안내 + 상대지표(T존−볼) 가중 자동 상향.
- **왜**: 사용자는 재촬영으로 결과를 검증한다 — 세션 간 흔들림이 신뢰를 깎는 1순위.
- **게이트**: 하니스에 2세션 시나리오 추가(같은 프로필, 다른 변형 → 같은 타입 비율).

### v3.0 — 데이터 플라이휠 (ROLLOUT 4단계와 연동)
- **무엇**: `/collect` 익명 측정 수집(ops/vision-proxy.worker.js 스캐폴드 준비됨, 동의 문구 필요)
  → 주기적으로 calibrate.mjs에 넣어 CAL 자동 제안 → 분기마다 엔진 버전 업.
  결과·주문 전환 데이터와 결합하면 "타입별 재구매율"로 판정 품질을 사업 지표로 검증 가능.
- **전제(대표 결정)**: 개인정보처리방침에 수집 항목 명시 + 옵트인 UI(연재와 문구 확정).
- **왜**: 룰베이스 엔진의 상한은 결국 데이터 — 수집 없이는 v2.x 수준에서 멈춤.

### v3.1 — AI 정밀 분석 옵트인 (베타)
- **무엇**: 희망자에 한해 부위 사진을 Workers 프록시로 vision 모델에 보내 정밀 리포트
  (스캐폴드: ops/vision-proxy.worker.js, 미배포). 룰베이스 판정과 병기해 상호 검증 데이터 축적.
- **전제**: v3.0의 동의 체계 + Anthropic API 키(대표) + 비용 상한 설정.
- **주의**: "사진은 기기에서만 처리" 문구가 바뀌는 것 — 옵트인 화면에서 명시적으로 구분할 것.

## 하지 않기로 한 것 (이유와 함께)
- **모공 지수의 판정 가중 상향** — 640px 셀피에서 모공 2~3px, 물리적 한계. 표시용으로만.
- **딥러닝 피부 분류 모델 온디바이스 탑재** — 학습 데이터가 없다. v3.0 데이터가 쌓인 뒤에나 검토.
- **설문 축약** — 사진 신뢰도가 실측으로 검증되기 전까지 설문이 안전망.
