# 진단 파이프라인 취약점 목록 (2026-09-01, 합성 스윕 기준)

측정 방법: `test/harness/run-baseline.mjs` — 7개 피부 프로필 × 13개 촬영 변형(노출·감마·WB·노이즈·블러·기울어진 조명·프레이밍) 합성 이미지 + 설문 15,552조합 전수. 수치는 `test/baseline/*.json`.

## 이번 세션에서 수정한 것 (✅)

### F1. 무광 피부가 유분 만점으로 측정 ✅ 수정
- **증상**: 완전 건성(무광) 합성 피부의 광택이 shine≈0.12로 측정 → shineFull(0.11) 초과 → T존 유분지수 96. 사진이 건성/지성을 전혀 구분 못 함(베이스라인: veryDry 사진+중립 설문 → **B지성**).
- **원인**: 분위수 문턱(p60+0.55·(p97−p60))은 분포 '모양'만 봐서 균일 노이즈 피부에서도 상수 비율(~12%)이 걸림. 실제 광택이 늘면 문턱이 같이 올라 값이 *내려가는* 비단조성도 확인(dry 0.052 < veryDry 0.123).
- **영향**: 치명 — 사진 유분축 전체 무효.
- **수정**: 스페큘러 물리 기준으로 교체 — "평균 피부보다 확 밝고(V>meanV×1.12) 채도가 빠진(S<0.26)" 픽셀. 마스크 탈락 하이라이트(흰색≠피부색)와 클리핑(rawMx≥252) 스페큘러는 피부 블록 위에서만 재인정.
- **효과**: veryDry Sp [0.74,0.13,0.13]→[0.09,0.83,0.09]. 타입 매트릭스가 의미 있게 분리(아래 표).

### F2. 붉은기 측정이 감마 변화에 붕괴 ✅ 수정
- **증상**: 같은 트러블 피부, 감마만 바꾸면 redness 0.050→0.001. 타입 C→B 반전.
- **원인**: ① 진하게 붉은 픽셀이 피부색 마스크(isFaceSkin nr<0.475)에서 탈락해 블로치 '가장자리'만 측정 ② r/(g+1) 비율이 감마에 민감.
- **수정**: 느슨한 피부 마스크(isSkin) 위 rg-색도 오프셋(nr > 중앙값+0.03)으로 교체. 노출 불변.
- **효과**: 붉은기 idx 변형간 흔들림 49→22.

### F3. 모공 측정이 항상 0 ✅ 수정
- **증상**: 모공 밀도를 아무리 올려도 poreDen=0.000, 노이즈를 넣어야만 값이 생김(노이즈를 모공으로 측정).
- **원인**: 5×5 창 평균과 비교하는데 창 크기≈모공 크기라 창 평균이 모공 자체가 됨.
- **수정**: 반경 4px 링 대비 + 노이즈 적응 문턱(이웃차 평균만큼 상향) + CAL 재보정(poreDenLo 0.010→0.0008, span 0.045→0.006).
- **효과**: 프로필 간 단조 구분(veryDry 0.0003 → oily 0.0020), 노이즈 오탐 9배 감소. ⚠️ 여전히 가장 약한 지표(블러에 0, 표시지수 흔들림 큼) — 아래 R2.

### F4. 사진 가중 q=0.5 하드컷 ✅ 수정
- **증상**: 품질 q가 0.49↔0.51을 오가면 사진 반영이 0%↔45%로 반전 — 재촬영 시 결과 튐.
- **수정**: q 0.35~0.65 구간 선형 램프. q≥0.65 동작은 기존과 동일(기존 결과 보존).

### F5. 연출(스캔 씨어터)과 결과의 모공 숫자 불일치 ✅ 수정
- **원인**: regionTheater는 구식 lap 기반 poreP, 결과는 poreDen 기반 — 다른 숫자를 말함.
- **수정**: 같은 상수·같은 커브 사용(diagnose-bw.html).

### F6. 엔진 복붙 중복(페이지 2개) ✅ 구조 해결

## 2차 강화 (2026-09-01 같은 세션, 엔진 v2.1.0)

### S1. 점상 트러블 vs 넓은 홍조 구분 ✅
- **문제**: 붉은기를 총량으로만 재서 넓은 홍조(민감·상기)도 여드름으로 오판 — 합성 flushed 프로필이 C트러블로 감.
- **수정**: 붉은 픽셀을 연결요소(블롭)로 나눠 점상(redSpot, ≤피부 2%)만 트러블 축에, 대면적(redFlush)은 '홍조 주의' 플래그로 분리.
- **검증**: flushed 프로필 redness 0.244 → redSpot 0.002 / redFlush 0.239 분리, 판정 A건성 + 홍조 플래그(4a).

### S2. 촬영 순간 키포인트 ROI + 오염원 제외 ✅
- **문제**: 고정 중앙 68% 박스라 프레이밍이 어긋나면 눈썹·눈·입술이 측정에 섞임 — 입술이 프레임에 들면 트러블 축 +14점 상당 오염(4b).
- **수정**: 엔진에 opts.roi/opts.exclude 추가. 페이지가 촬영 순간 BlazeFace 키포인트로 부위별 ROI를 잡고 눈×2·입·(볼 모드는 코까지) 제외 원을 넘김. 키포인트 없으면(업로드 등) 기존 중앙박스 폴백.
- **검증**: 오염 편차 0.0178 → 0.0028 (6배 감소, 4b).

### S3. 연사 3장 중앙값 ✅
- **문제**: 한 장 측정은 센서 노이즈·자동노출 출렁임에 그대로 노출.
- **수정**: 촬영 버튼 1번 = 110ms 간격 3장 → 필드별 중앙값(aggregateBurst). 썸네일은 q 최고 샷.
- **검증**: 노이즈 조건 측정 편차 0.0145 → 0.010 (31% 감소, 4c).

### S4. 축별 사진 신뢰도 ✅ (완화 적용)
- **근거**: 사진은 유분(스페큘러 직접 측정)엔 강하고, 건조는 '광택 없음' 간접 추론이라 약함 — 설문이 당김·각질 체감을 더 잘 잼.
- **수정**: fuse에서 사진 가중에 axisRel [유분1, 건조0.85, 트러블0.95] 곱함. 강한 버전([1,0.75,0.9])은 일관성 0.954로 떨어져 완화(0.963, 균등 0.967 대비 -0.4pp 비용으로 원리 반영).

### S5. 건조 축 직접 신호 — 각질·거칠기 (v2.2) ✅
- **문제**: 건조는 "광택이 없다"는 간접 추론뿐 — 무광이지만 건강한 피부와 각질 들뜬 건성을 구분 못 함.
- **수정**: 3~9px 밴드패스(박스평균 차) 거칠기 측정, 노이즈 기여분(0.45×이웃차) 차감. 무광일 때만 dry 최대 +18% 보정 + 표시지수 idx.flake + 근거 문구("각질 신호가 보여 수분 보강을 우선했어요").
- **검증**: flake 지수 veryDry 86 / dry 60 / normal·oily 10 단조 구분, 노이즈 사진 오탐 0 근처, 일관성·타입 매트릭스 무변화(strengthen-v3).

### S6. 데이터→보정 진화 루프 (v2.2) ✅
- **무엇**: 진단 1회마다 측정값(숫자만·사진 없음)을 기기 localStorage에 기록 → ?bfmdebug 결과 화면 [복사]로 내보내기 → `test/harness/calibrate.mjs`가 실측 분포로 CAL 제안 + troubleMin↔C비율 표(대표의 배분 결정 도구).
- **의미**: 엔진이 실사용 데이터로 계속 재보정되는 경로 — 향후 단계는 `engine/ROADMAP.md`.

## 남은 리스크 / 수정 안 한 것 (R)

### R1. diagnose.html(라이브)에 옛 엔진이 그대로 있음 — 난이도 낮음·결정 필요
측정 버그 F1~F3는 라이브 코드에도 존재. 단, PR #1~#6이 대기 중이라 지금 diagnose.html을 건드리면 머지 충돌. **롤아웃 순서 결정 필요**(NEXT.md 참고).

### R2. 모공 지표는 여전히 근거 약함 — 난이도 중
640px 셀피에서 모공은 2~3px — 물리적으로 한계. 유분 판정 가중은 0.10뿐이지만 **표시 지수(코 모공·결)는 사용자에게 그대로 보임**. 실기기 9회 측정으로 재보정 전까지 결과 화면에서 모공 지수를 빼거나 '참고' 표기 검토.

### R3. 설문 조합공간의 C(트러블) 쏠림 — 판단 필요(대표 몫)
전수 15,552조합 중 54.3%가 C, 경계(±0.02) 밀집 10.6%. 트러블 문항에 조금만 답해도 C로 감(troubleMin 0.28 하향의 대가). 실제 사용자 분포는 균등이 아니므로 54%가 실측 비율은 아니지만, **'가끔 한두 개' 응답만으로 C가 되는 경계**는 실기기 검증 항목. troubleMin은 사업 결정(A/B/C 목표 배분)이라 자율 수정 안 함.

### R4. 업로드 경로는 얼굴 검증 없음 — 난이도 중
파일 업로드로 벽·손바닥 등 '피부색 비슷한 비얼굴'을 넣으면 게이트(noskin)를 통과할 수 있고 지수가 그럴듯하게 나옴. 촬영 경로는 BlazeFace가 기회주의적으로 확인하지만 업로드는 없음. faceSeen=false면 q×1.08 미적용뿐. → 업로드 사진에도 BlazeFace 1회 실행해 얼굴 없으면 '설문 위주 판정' 플래그 강화 검토(모델 로드 1~2초 비용).

### R5. 강한 WB 캐스트(형광 블루 등)에서 유분 과소측정 — 난이도 중
coolWB 변형에서 oily tzShine 0.12→0.05. 실내 셀피 자동WB에선 드물지만, 촬영 게이트에 색온도 힌트 추가 여지.

### R6. 페르소나·문항이 조명 경계 근처 사용자를 못 잡는 문제(경계밀집 15.7%)
1·2위 격차<0.03인 설문 조합이 15.7% — 답 하나로 타입이 바뀜. 완화하려면 경계일 때 '낮은 확신' 표시가 이미 있음(band). 결과 페이지 lc=1 문장형 표시가 이를 커버 — 유지.
